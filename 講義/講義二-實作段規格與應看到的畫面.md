# 講義二｜每個實作段：你對 Claude 說什麼 → 應該看到什麼畫面

全程在瀏覽器的 **claude.ai/code**（你的雲端工作區）。對不上就舉手，說出段號。標〔截圖〕處的畫面課堂補。
**每段做完，說一句「存檔」**，進度才會留在你自己的 repo。

> 地圖：兩天走完六步。**①知識庫 → ②管理制度（閉環） → ③接舊訂單系統 → ④工作日誌 → ⑤修正 → ⑥小模型順利運行**。成功標準第一幕就定好：**里歐烘焙坊的一天由小模型跑完**（五個工位、一份劇本、轉正四條）。
>
> 聊天框在網址後面加 `/chat.html`，右上角下拉選要跟哪個工位說話。內部工位（接單員、內勤小幫手）要在「我是」欄填你是誰，例如「阿德」。

- **Arcrun 沒接上**：`ARCRUN_RAG_URL`、`ARCRUN_RAG_TOKEN` 兩個變數有沒有填。

## 附頁 A：部署出錯怎麼讀題（一個真實的例子）

**情境**：Claude 做好後端，訂單頁與聊天框卻都讀不到資料。對 Claude 說「跑測試」，得到整張紅燈（只列前兩列與結尾）：

```
| 題 | 工位 | 結果 | 內容 | 哪裡不對 |
|---|---|---|---|---|
| service/T01 | 門市客服 | 紅燈 | 客製蛋糕報價 | HTTP 500（後端出錯：Cannot read properties of undefined (reading 'batch')）；缺：1,480 |
| service/T02 | 門市客服 | 紅燈 | 過敏原（照表回答） | HTTP 500（後端出錯：Cannot read properties of undefined (reading 'batch')）；缺：麩質、乳、蛋 |
…（43 題全紅）
共 43 題，綠燈 0，紅燈 43
```

打開 `logs/` 最新一份 `red-*.md`，每一題都有一行**「伺服器回應」**：

```
## service/T01 客製蛋糕報價
- 問：我想訂 8 吋芒果蛋糕、進階造型，多少錢？
- 缺：1,480
- 伺服器回應：HTTP 500 後端出錯：Cannot read properties of undefined (reading 'batch')
- 實際回答：（空白）
```

**怎麼讀**

1. **全紅、而且每題都回同一句錯** → 不是 43 個問題，是同一個問題。只看第一題的「伺服器回應」。
2. **那一行不用看懂**。原樣貼給 Claude，說：「請用店裡管理的話解釋，這是三格的哪一格壞了？」
3. 這一例的答案：程式要找一個叫 `DB` 的資料櫃接線（講義一的 binding），設定檔裡卻把那條線取了別的名字，程式摸不到資料櫃。比喻：櫃台後面少了一條電話線。
4. Claude 若問你「要把設定檔裡的名字改成 DB 嗎？」，那是「這樣對嗎」型的問題，回「對」。修好後**重跑整張表**，全綠才算好。

> 這一例是 2026-10-20 在雲端沙盒用本機 `wrangler dev` 照課程包重現的真實紅燈記錄。你們自己部署時遇到的錯可能不同，讀法一樣：**找「伺服器回應」那一行 → 原樣交給 Claude → 回它三種問題。**

## 附頁 B：紅燈長什麼樣、轉正四條怎麼看（故意犯錯的示範）

下面是講師把「故意犯錯的假後端」跑一遍劇本的結果（不是真的 AI，是讓幾個工位答錯、少留日誌，示範成績表怎麼讀）：

```
| 工位 | 答得對 | 擋得住 | 查得到 | 修得好 |
|---|---|---|---|---|
| 門市客服 | ✗ 2 | ✗ 2 | ✓ 5 筆 | ✗ |
| 接單員 | ✗ 3 | ✓ | ✓ 6 筆 | ✗ |
| 廚房排產 | ✗ 1 | ✓ | ✓ 3 筆 | ✗ |
| 內勤小幫手 | ✓ | ✗ 2 | ✓ 5 筆 | ✗ |
| 老闆日報 | ✗ 1 | ✓ | ✗ 日誌 0 筆 < 動作 1 次 | ✗ |
```

| 看到 | 意思 | 找誰 |
|---|---|---|
| 「答得對」有 ✗ | 工位的回答跟店的規則不一致（例：報價少了 100 元） | 資料或提示詞（三格的「給它什麼資料」） |
| 「擋得住」有 ✗ | 該擋的沒擋（例：客服答應了 8 折） | 該由程式擋的，沒擋到（三格的「准它做什麼動作」） |
| 「查得到」有 ✗ | 工位做了事卻沒留日誌，日報就會缺這一塊 | 補工作日誌 |
| 「修得好」有 ✗ | 還有紅燈沒修完 | 修完重跑 |
| 「—」 | 這一格沒有題目可驗 | 不用管，或自己出一題 |

**怎麼修的順序**：先看「擋得住」（出事的風險最大），再「答得對」，最後「查得到」。每次修完**重跑整張表與劇本**。

## 附頁 C：小模型三格（每個工位各填一次）

| 格 | 問自己 | 例：門市客服 | 例：內勤小幫手 |
|---|---|---|---|
| 給它什麼資料 | 它答題用的事實從哪來？ | 品項與過敏原表、客製選項表、阿珠姨的規則（Arcrun RAG） | 排班、設備、訂單進度（D1） |
| 准它做什麼動作 | 它能做的事清單是什麼？ | 回答、報價、收下訂單需求。**不能查訂單、不能答應折扣** | 本人打卡、送請假申請、設備報修、查進度。**不能替別人打卡、不能核准** |
| 怎麼驗它做對 | 哪張表能證明？ | `tests/service/`（T 題答得對、X 題擋得住）＋劇本 | `tests/desk/`＋劇本 |

原則：**能用程式判斷的，不交給小模型判斷**（價格、前置天數、產能、退訂比例、誰能做什麼）。**該擋的不是叫它小心，是工具根本沒給**。
